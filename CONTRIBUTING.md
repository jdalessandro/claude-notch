# Contributing

Thanks for helping! The core logic and the hook forwarder are a SwiftPM package that builds and tests with the Command
Line Tools. The app and its Live Activity widget are built from an Xcode project generated by
`scripts/gen_xcodeproj.py`, which needs Xcode 27.3+ and a signing team (`.xcode-team`, never committed).

## Build the app

You need Xcode 27.3+ and an Apple developer team (a free Personal Team is enough). Ad-hoc signing isn't: the island's
Allow / Deny buttons are App Intents, which the system only runs for properly signed apps.

```bash
echo YOUR_TEAM_ID > .xcode-team   # 10 characters, from Xcode ▸ Settings ▸ Accounts (never committed)
make bundle                       # generates the Xcode project and builds dist/Notchbot.app
make install                      # or: build and copy to /Applications
make demo                         # launch with synthetic agents, no hooks needed
make snapshots                    # re-render docs/screens/*.png
```

## Setup

```bash
git clone <your fork> && cd notchbot
make build test          # swift build && swift test
make lint                # swift-format, strict
```

Requirements: macOS 27.3+ (Live Activities on the Mac), Swift 6 toolchain; Xcode 27.3+ for the app. Heads-up: with only the Command Line Tools installed, the compiler
occasionally fails with `plugin for module 'TestingMacros' not found`. That is a toolchain flake; re-run the command.

## Layout

| Path | Contents |
|---|---|
| `Sources/NotchbotCore` | Pure logic with no UI: events, session state machine, transcript/usage parsing, IPC, installer, preferences. **Everything testable lives here.** |
| `Sources/notchbot-hook` | The forwarder Claude Code invokes. Must never block or break a session. |
| `App/` | The host app: `AppModel`, Live Activity host, settings, menu-bar item. |
| `Shared/` | Code compiled into both the app and the widget: island views, App Intents, activity attributes. |
| `Widget/` | The widget extension that draws the Live Activity. |
| `Tests/NotchbotCoreTests` | Swift Testing suites, one file per area. |

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the data flow and design rules, [docs/RESEARCH.md](docs/RESEARCH.md)
for how Claude Code is observed, and [docs/RELEASING.md](docs/RELEASING.md) for cutting a release (maintainers).
User-facing docs live in the [README](README.md) and [docs/GUIDE.md](docs/GUIDE.md); update them with any behavior change.

## Before you open a PR

- `make test` and `make lint` pass (`make format` fixes most style findings).
- New behavior in `NotchbotCore` comes with tests. UI-only changes include a screenshot (`make snapshots`).
- Keep the hook forwarder fast and silent; anything it prints goes to Claude Code.
- Don't use `@State`/`@Binding` property wrappers in views: they are macros that require a compiler plugin the Command
  Line Tools don't ship. Keep view state in the `@Observable` models instead.
- Small, focused PRs; describe the *why*.

## Reporting bugs

Use the bug template and, if relevant, attach a redacted excerpt from the diagnostics log (see SECURITY.md).
